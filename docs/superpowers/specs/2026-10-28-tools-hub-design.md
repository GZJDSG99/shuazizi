# 刷子zi 工具集合 — 设计规格

**日期：** 2026-10-28  
**状态：** 已确认；实现计划见 `docs/superpowers/plans/2026-10-28-tools-hub.md`  
**目标：** 将现有「掐指一算」清单能力收进工具集合小程序「刷子zi」；首页宫格入口；按工具分包，便于后续扩展。

**前置：** 基于已实现的多清单「掐指一算」小程序（见 `2026-10-26-decoration-budget-miniprogram-design.md` 及后续多清单改造）。

---

## 1. 目标与成功标准

- 小程序对外品牌为 **刷子zi**
- 启动后看到宫格工具箱首页，而非直接进入清单列表
- **掐指一算** 作为其中一个可进入的工具，原有多清单 / 记账 / 备份 / 长图能力保持可用
- 首页另有 **4 个「敬请期待」占位格**，点击仅提示，不跳转
- 无底部 Tab；导航为页面栈
- 第一版即按工具拆分包，为后续大量工具预留结构

成功标准：

- 冷启动 → 宫格首页 → 点「掐指一算」→ 原清单列表与后续流程正常
- 从清单返回可回到宫格首页
- 占位格灰态可见，点击 toast「敬请期待」或等价文案
- 新增工具时：建分包 + 注册表加一项即可出现在宫格，无需改首页业务逻辑

## 2. 范围

### 2.1 第一版包含

- 主包工具首页（宫格布局）
- 工具注册表驱动宫格渲染
- 掐指一算整组迁入独立分包 `packageQizhi`
- 品牌文案：对外「刷子zi」；工具内仍称「掐指一算」
- 占位工具 4 个（仅配置，不建空分包）
- 保留掐指一算现有本地数据与迁移逻辑（存储 key 不变）

### 2.2 第一版不做

- 底部 Tab / 「我的」页
- 账号、云同步、工具市场、自定义宫格排序
- 为占位工具创建空分包或具体工具名
- 主包与分包之外的多端（H5 / App）
- 改掐指一算内部产品功能（仅迁移路径与入口）

## 3. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 框架 | 原生微信小程序 | 与现网一致 |
| 结构 | 主包首页 + 按工具分包 | 工具会很多，控制主包体积、边界清晰 |
| 入口配置 | `config/tools.js` 注册表 | 首页只读配置渲染，扩展成本低 |
| 数据 | 各工具本地 Storage，独立 key 前缀约定 | 无后端；避免工具间踩 key |

## 4. 信息架构与路由

```
启动
  └─ pages/home/home          # 刷子zi 宫格首页（主包，app.json pages 首位）
        └─ 掐指一算（enabled）
              └─ packageQizhi/pages/lists/lists
                    └─ packageQizhi/pages/index/index?listId=
                          ├─ item-edit
                          └─ category
```

- 无底部导航栏
- 清单页 `navigateBack` / 系统返回 → 回到宫格首页
- 导航栏标题：首页「刷子zi」；掐指一算分包内沿用现有各页标题（列表页可为「掐指一算」）
- `app.json`：`pages` 仅挂主包页（至少 `pages/home/home`）；`subpackages` 注册 `packageQizhi`
- 建议对掐指一算配置 `preloadRule`（从首页预下载），降低首次进入分包白屏感

## 5. 工具注册表与首页宫格

### 5.1 注册表字段（`miniprogram/config/tools.js`）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识，如 `qizhi` |
| `name` | string | 宫格标题 |
| `desc` | string | 一行简介（可选展示） |
| `icon` | string | 图标资源路径或约定 key |
| `path` | string | 可进入时的页面路径（分包绝对路径） |
| `enabled` | boolean | `true` 可跳转；`false` 占位 |
| `badge` | string | 可选角标，占位可用「即将上线」 |

### 5.2 首页行为

- 宫格约 **3～4 列**（实现时按屏宽微调，竖屏优先可读）
- 第一版条目：**1 个真工具（掐指一算）+ 4 个占位**，共 5 格
- `enabled: true`：`wx.navigateTo` 到 `path`
- `enabled: false`：视觉灰态 + 「敬请期待」；点击 `wx.showToast`，不跳转
- 占位 **不写具体未来工具名**，避免占坑后改名

### 5.3 扩展约定

1. 新建分包目录与页面  
2. 在 `subpackages` 注册  
3. 在 `tools.js` 增加 `enabled: true` 一项  
→ 首页自动展示，无需改首页 JS 业务分支

## 6. 分包迁移与目录

建议结构：

```
miniprogram/
  app.js / app.json / app.wxss
  config/
    tools.js                 # 工具注册表
  pages/
    home/                    # 宫格首页
  packageQizhi/              # 掐指一算分包
    pages/
      lists/
      index/
      item-edit/
      category/
    utils/
      storage.js
      calc.js
      backup.js
      canvas-share.js
      id.js
  images/                    # 公共或首页图标（可按需拆）
```

迁移原则：

- 掐指一算页面与专用 utils **整组进入分包**；主包不 `require` 分包业务 utils
- 页面内相对路径 `require` 随目录调整
- 凡写死的旧路径（如 `/pages/lists/lists`）改为分包路径 `/packageQizhi/pages/lists/lists`

---

## 7. 数据与兼容

- 掐指一算 **Storage key、多清单结构、旧版单账本迁移逻辑保持不变**
- 换机仍用现有剪贴板备份 / 导入
- 未来新工具使用独立 key 前缀（建议 `tool_<id>_...`），禁止复用掐指一算 key
- 本规格不改变清单内部字段与计算规则

## 9. 错误与空态（首页）

- 注册表为空：极少见；可展示「暂无工具」
- 真工具 `path` 缺失或跳转失败：toast 失败提示
- 占位点击：统一「敬请期待」，不进入任何页

掐指一算分包内错误/空态保持现有行为。
