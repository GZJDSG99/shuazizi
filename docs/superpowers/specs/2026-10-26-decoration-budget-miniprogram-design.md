# 装修预算清单微信小程序 — 设计规格

**日期：** 2026-10-26  
**状态：** 待用户确认后进入实现计划  
**目标：** 个人装修账本，竖屏好用，分类清晰，自动汇总，可分享分类汇总长图。

---

## 1. 目标与成功标准

用户正在装修，需要在手机上管理「预估 vs 实际」花费。成功标准：

- 打开即可记账，无需登录、无需服务器
- 自定义分类，价格按分类一目了然，总价自动算
- 竖屏操作舒适（大点击区、卡片列表，不做横向宽表）
- 一键能生成「总览 + 分类小计」长图，保存相册或转发微信

## 2. 范围

### 2.1 第一版包含

- 原生微信小程序（单份清单）
- 本地存储（`wx.setStorageSync`）
- 自定义分类：增删改名、排序
- 费用条目：增删改，字段见数据模型
- 首页横向分类标签浏览 + 顶栏精简总览
- 自动计算：单条差额、分类小计、总预估/总实际/总差额
- 长图分享：仅总览 + 各分类小计（不含明细行）

### 2.2 第一版不做

- 登录 / 云开发 / 多端同步
- 多套清单
- 完整明细长图 / 导出 Excel
- 导入外部表格
- 预设示例分类或示例数据

## 3. 技术选型

| 项 | 选择 | 理由 |
|----|------|------|
| 框架 | 原生微信小程序（WXML / WXSS / JS） | 体积小、真机路径常规、竖屏控件可控 |
| 数据 | 本地 Storage | 用户明确选择「仅本机」 |
| 长图 | 离屏 Canvas 2D 绘制 | 无后端依赖，可保存/转发 |

项目建议结构（实现时可微调）：

```
miniprogram/
  app.js / app.json / app.wxss
  pages/
    index/          # 首页账本（标签 + 列表）
    item-edit/      # 新增/编辑条目
    category/       # 分类管理
  utils/
    storage.js      # 读写与默认结构
    calc.js         # 汇总与差额
    canvas-share.js # 长图绘制
  images/
```

## 4. 信息架构与页面

### 4.1 首页（`pages/index`）— 布局 B

- **顶栏：** 标题「装修预算清单」；右侧「分享」
- **精简总览卡：** 预估合计 / 实际合计 / 差额（超支偏红、结余偏绿）
- **横向分类标签：** 可左右滑动；展示分类名（推荐附带该分类小计）；末尾「管理」进入分类页
- **当前分类条目列表：** 竖向卡片；展示名称、预估、实际、差额（或「—」）、品牌规格摘要
- **待填提示：** 未填的预估/实际用浅黄底标出
- **悬浮/底部「＋」：** 新增条目，默认归属**当前选中分类**
- **点卡片：** 进入编辑页

空状态：

- 无任何分类 → 引导「先建一个分类」
- 有分类但当前分类无条目 → 「还没有项目」+ 新增按钮

### 4.2 编辑条目（`pages/item-edit`）

字段：

| 字段 | 必填 | 说明 |
|------|------|------|
| 所属分类 | 是 | 选择器，来自自定义分类 |
| 项目名称 | 是 | 文本 |
| 预估金额 | 否 | 数字，最多 2 位小数；浅黄可填 |
| 实际金额 | 否 | 同上 |
| 品牌/规格备注 | 否 | 文本 |
| 备注 | 否 | 文本 |

只读展示：差额（自动）。任一侧金额缺失则显示「—」。

操作：保存、取消；已有条目可删除（需二次确认）。

### 4.3 分类管理（`pages/category`）

- 列表展示：名称、条目数
- 新建分类、改名
- 拖拽或上下按钮调整 `order`（实现优先可用上下调序，拖拽为加分项）
- 删除保护：该分类下仍有条目时禁止删除，提示先迁移或删光条目
- 分类顺序与首页标签从左到右一致

## 5. 数据模型

单份清单，Storage key 建议：`decoration_budget_v1`。

```js
{
  version: 1,
  updatedAt: "ISO-8601",
  categories: [
    { id: string, name: string, order: number }
  ],
  items: [
    {
      id: string,
      categoryId: string,
      name: string,
      estimated: number | null,  // 元
      actual: number | null,
      brandSpec: string,
      note: string,
      order: number
    }
  ]
}
```

约定：

- `id` 使用足够唯一的本地生成方式（如时间戳 + 随机串）
- **差额不落库**，展示与汇总时计算
- 金额以「元」为单位存储；输入允许整数或最多 2 位小数
- 首次启动写入空结构：`categories: []`, `items: []`，不预置数据

## 6. 计算规则

- 单条差额：`actual - estimated`；任一侧为 `null` → 该条差额为不可用（UI 显示「—」）
- 分类预估小计：该分类下所有非空 `estimated` 之和
- 分类实际小计：该分类下所有非空 `actual` 之和
- 分类差额：`分类实际小计 - 分类预估小计`（用于标签角标与长图；若该分类预估与实际皆无任何已填项，差额可显示「—」）
- 总预估 / 总实际：全清单同上累加
- 总差额：`总实际 - 总预估`

## 7. 长图分享

用户选择：**仅总览 + 分类小计**（不含明细行）。

内容结构：

1. 标题：装修预算清单（预估）
2. 副文案：单位：人民币（元）
3. 三列汇总：预估合计、实际合计、差额
4. 元信息：生成日期、分类数、条目数（可选）
5. 按 `order` 列出每个分类一行：分类名 + 预估小计 / 实际小计 / 差额
6. 页脚：由本小程序生成

交互：

- 首页点「分享」→ 绘制 Canvas → 预览 → 「保存到相册」和/或「转发给朋友」
- 需申请相册权限；失败时 toast 说明原因

## 8. 视觉方向

- 主色：深蓝系（约 `#1e4a8c`），对齐用户提供的表格表头风格
- 待填金额：浅黄底（约 `#fff8d6`）
- 差额：>0 偏红，<0 偏绿，=0 中性灰
- 字体：系统字体；金额使用等宽/tabular 数字便于对齐
- 避免宽表；一律竖向卡片与标签导航

## 9. 错误处理与数据安全

- Storage 读写失败：toast，保留内存中上次成功状态，避免静默清空
- 删除条目 / 删除空分类：确认弹窗
- 无网络依赖；分享仅依赖本机 Canvas 与微信客户端能力
- 换机或清缓存会丢数据：第一版接受该风险（规格外备份能力后续再做）

## 10. 测试要点（实现阶段）

- 空清单 → 建分类 → 加条目 → 改金额 → 总览数字正确
- 切换标签只显示对应分类；「＋」落到当前分类
- 预估/实际单侧缺失时差额与汇总符合第 6 节
- 分类排序后首页标签与长图顺序一致
- 有条目时无法删除分类；清空后可删
- 长图在真机可保存相册；无相册权限时有明确提示
- 竖屏小屏（如 iPhone SE 宽度）标签可横滑、按钮可点
